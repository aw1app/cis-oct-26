Observed failure points

The failed cases point to gaps in transaction safeguards, clear on-screen feedback, and responsiveness under load.

Transfer flow and safety

OTP delivery did not complete within 60 seconds for a new payee, interrupting transfer authorization (TC03 / DEF-101, Critical).

After network loss, automatic retry caused a duplicate debit, creating a transaction-integrity risk. The transfer-history check remains blocked until this is fixed (TC06 / DEF-102, Major; TC13 blocked).

Interface and error feedback

On 5-inch devices, the confirmation button was hidden, preventing users from completing the confirmation step (TC09 / DEF-103, Minor).

An invalid beneficiary account produced a generic error instead of identifying the field, leaving the user without actionable correction guidance (TC12 / DEF-104, Major).

System response under load

At a peak load of 500 users, transfer response time exceeded the 5-second target; the recorded test time was 12.4 seconds (TC15 / DEF-105, Major).

Together, these results show failures in authentication delivery, retry handling, actionable validation, and performance at the tested load.

Prioritized recommendations

Proposed triage order based on financial impact, security, and user impact; priorities are not fields in the source CSV.

PriorityFocusRecommended actionDefect link and success check
P0 · Immediate Prevent duplicate transfers Make transfer submission idempotent and debit/credit processing atomic. After a timeout or connection loss, check the transaction's authoritative status before retrying; show a clear pending state while it is resolved. TC06 / DEF-102; TC13 is blocked. Repeated requests must never create a second debit, and transfer history must reconcile the final result.
P1 · High Secure OTP completion Monitor OTP delivery, provide a controlled resend path with expiry and attempt limits, and fail closed with a useful message when authorization cannot complete. Do not bypass OTP to improve completion. TC03 / DEF-101. Verify authorized users can complete OTP within the 60-second expectation and failed or repeated attempts remain rate-limited and auditable.
P1 · High Peak-load performance Profile the transfer path at and above expected peak load, remove bottlenecks, and monitor latency and timeouts. Keep the transaction state visible so users do not resubmit during slow responses. TC15 / DEF-105. Meet the existing 5-second target at 500-user peak load and verify slow or timed-out requests cannot result in duplicate transfers.
P2 · Medium Actionable validation Return clear, field-level beneficiary-account errors, preserve safe form input, and keep server-side validation authoritative. TC12 / DEF-104. Invalid account input identifies the beneficiary field and explains how to correct it without exposing sensitive data.
P2 · Medium Responsive confirmation Rework the confirmation layout so the primary action stays visible or predictably reachable on small screens; check larger text, orientation, and accessibility settings. TC09 / DEF-103. Confirm button and transfer summary remain visible, readable, and operable on the tested 5-inch layout.
