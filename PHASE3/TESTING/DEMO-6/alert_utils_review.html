Code Review: alert_utils.py

Maintainability and safety findings, ordered by impact.

  1. High

    SQL is built through string concatenation

    get_alerts_by_source inserts source_name directly into the query at line 28 and executes it at line 29. If an attacker can influence this value, SQLite may interpret part of it as SQL logic rather than as a literal source name. Depending on how the function is exposed, this could return alerts beyond the requested source or cause query errors.

    Python's SQLite execute() rejects multiple SQL statements, which limits stacked-statement attacks, but does not prevent an input from changing the meaning of this single statement. Bind the input as a parameter so it is treated strictly as data:

    cursor.execute(
    "SELECT * FROM alerts WHERE source = ?",
    (source_name,),
)

    A regression test should pass a source name containing SQL punctuation and verify that it is treated as an exact literal value.

  2. High

    Credentials are embedded in source

    The database password and admin API key are hard-coded at lines 21–22, and neither is used in this module. This couples secrets to the codebase and makes rotation and environment separation harder. Remove the literals, load secrets from an approved configuration or secret store, and rotate them if they are real.

  3. Medium

    Critical and warning formatters duplicate logic

    Lines 3–9 and 12–18 repeat message assembly and escalation logic; only the alert label differs. A shared formatter with the label supplied as an argument would keep future wording or behavior changes consistent.

  4. Medium

    Database connection is not explicitly closed

    The connection is opened at line 26, but lines 27–30 return without closing it. Repeated calls can retain database resources longer than intended. Use a context-managed connection or ensure cleanup in a finally block.

  5. Medium

    Escalation multiplier is a magic number

    The 1.5 multiplier appears at lines 7 and 16, while the message spells it as “150%.” A named constant or an explicit policy setting would make the escalation rule easier to understand and change consistently.

  6. Medium

    Query selects every column

    SELECT * at line 28 makes the returned shape depend on the table schema and fetches columns the caller may not need. List the required columns explicitly to make the function’s data contract clear and resilient to schema changes.

Review scope: alert_utils.py. No source code was changed.
